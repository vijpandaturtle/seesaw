Seesaw

Accessible, pragmatic interpretability.

vijpandaturtle/seesaw v0.1.0

Overview

Models show unexpected behaviors at every stage of development, and interpretability has proven useful for finding them. But new models arrive faster than experts can study them. Seesaw uses AI agents to automate interpretability: monitor a behavior at runtime, audit a model when it surprises you, before you ship it or after you change it, and fix what you find. Newcomers get answers they can act on, and researchers get through more models, faster.

Scout behavior + examples → plan → Lens plan → results bundle → Quill bundle → critique report

Features

Pick what you want. Each one is compared with the simple option that doesn't look inside the model, and Seesaw tells you when the simple option is enough.

Monitor: catch it at runtime

Works today

Your model sometimes follows injected instructions or leaks its system prompt, and you want to flag it in production.

You bring
the behavior in a sentence, a few prompts where it happens, a few where it doesn't, and your model
You get
a detector on the model's activations, recommended only if it beats a text classifier trained on the same examples

Audit: find out if it's there, and why

Partly built

It did something you saw, you're about to ship it, or you just fine-tuned it and want to know what changed.

You bring
a behavior with examples, a checklist of known behaviors from the library, or the model before and after a change
You get
whether the behavior is built into the model and where it comes from, or where the two versions differ

The checklist runs one audit per behavior, and only prompt injection has a dataset and a pass/fail rule so far. Earlier audits aren't rerun on a new version yet.

Fix: remove it from the model

Partly built

Your model caves to pushback or refuses harmless requests, and you want it gone.

You bring
the behavior in a sentence, a few prompts where it happens, a few where it doesn't, and your model
You get
a change to the model that removes the behavior, recommended only if it beats a better prompt without breaking anything else

Fixes run and are checked for damage elsewhere, but not yet compared with a better prompt.

You never pick a method: Scout chooses a tested one from your examples, and you approve it before it runs. The full list of safety jobs, including the planned ones, is in the use-cases guide.

Get started

Install with the experiment stack, add an Anthropic key, and audit a behavior whose answer is already known, so you can check the verdict.

# install (Lens needs torch + TransformerLens)
uv venv .venv --python 3.12 && source .venv/bin/activate
uv pip install -e ".[experiments]"
cp .env.example .env   # set ANTHROPIC_API_KEY (and HF_TOKEN for Gemma or Llama)

# describe the behavior, with an example of it and one without, then approve at each gate
seesaw jobs submit "Uses the gender a job title implies to choose 'she' or 'he'" \
  --example "The nurse said that" --non-example "The person said that" \
  --action audit --model Qwen/Qwen2.5-1.5B --follow

--action is monitor, audit or fix; leave it out and Scout infers it. Longer examples, with the model's outputs, go in a YAML file passed with --behavior-file. seesaw jobs rerun <id> --model <other> runs the same experiment on another model.

The Three Agents

The agents currently run on Claude.

🔭

Scout

The Research Planner

A ReAct agent that turns your behavior and examples into a plan: it picks a tested method and writes its inputs, which are checked before you see them. When no method fits, it plans the experiments itself. It searches the literature only when you ask it to.

LangGraph ReAct · Firecrawl
🔬

Lens

The Experiment Runner

A LangGraph state machine that runs the chosen method first, then any extra experiments in the plan, interprets each result, and can queue follow-ups. It runs text models through TransformerLens and vision-language models through lever.

LangGraph StateGraph · TransformerLens · SAELens
🪶

Quill

The Reviewer

Critiques the results like a peer reviewer, with the method's verdict as the primary evidence. It flags methodological gaps and unsupported conclusions, and writes follow-up specs Lens can run.

LangGraph StateGraph
